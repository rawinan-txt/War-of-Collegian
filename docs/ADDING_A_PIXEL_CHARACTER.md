# Pixel characters: how it works and how to add one

All hero art is **original 8-bit-style pixel art generated by code** (no hand drawing, no third-party assets). A Node generator draws every frame on a 64x64 grid from a shared chibi rig plus a per-character definition, then writes PNG sprite strips and an animation config the game loads.

```
tools/pixel/png.js        PNG encoder/decoder (no dependencies)
tools/pixel/buf.js        64x64 RGBA buffer: rect, line, ring, outline, flash, fade, under...
tools/pixel/rig.js        the shared chibi student rig (head, hair, torso, arms, legs, face)
tools/pixel/anims.js      pose generators: idle 4, walk 6, attack 6, skill 10, hurt 3, death 6
tools/pixel/helpers.js    small bitmaps (heart, note, cross, tooth), cog, dome
tools/pixel/characters.js Bug Hunter definition + merges the roster
tools/pixel/roster.js     the other 11 heroes + the summoned dog
tools/gen-sprites.js      writes assets/characters/**.png, animations.json, animations.js
assets/characters/        generated sheets (committed)
```

Regenerate everything with `node tools/gen-sprites.js` (output is deterministic; a test fails if committed sheets are stale).

## Visual style (rig v2)

Big-head chibi: the head is 22 of 38 px (~58% of the figure), with large eyes (coloured iris + white sparkle), a dark inner outline plus a white outer outline, and hair with a lighter highlight band. Hair styles: short, swept, spiky, ruffled, long (with `hairLen` / `hairFlare`), sideponytail. The old pose keyframes still drive the new body through `mapHand` / `mapFoot` in `tools/pixel/rig.js`. Glasses are a `look.glasses` colour. Regenerate the overview with `node tools/character-sheet.js` (writes `docs/character-sheet.html`; a PNG screenshot is kept in `docs/character-sheet.png`).

## Animation state machine (runtime)

Priority: `death > hurt > skill > attack > walk > idle` (`animState(u)` in `index.html`).

- **walk** while the unit moved last frame, **idle** otherwise.
- **attack** plays for 0.5 s after an attack starts. Damage is applied by the combat code, never by animation frames: melee lands 0.25 s after the attack starts (frame 3 = impact); ranged units launch a projectile at the same moment and damage lands when it arrives. If the target dies first, the shot is lost. Stun or death cancels an unlaunched swing.
- **hurt** plays 0.25 s when HP is really lost (shield-only hits do not trigger it), at most once per 0.6 s.
- **death** is played by a visual-only corpse (`battle.corpses`) after the unit has left combat.
- Animation clocks advance only inside `update(dt)`, so pause and 2x speed behave correctly.

## Adding a new character

1. **Define it.** Add an object to `tools/pixel/roster.js` (copy a similar hero). Required fields:
   - `id` (must equal the hero `id` in the `heroes` table), `name` (folder file name), `title`, `faculty` (the hero's `f`), `folder` (`<faculty-folder>/<name>`), `skillMode`, `attackStyle`, `impact: {attack: 3, skill: 6}`
   - `look`: `skin, skinShade, shirt, shirtShade, eye, hair, hairStyle (short|spiky|bob|ponytail|long|bun|curly), bottom, bottomType (trousers|skirt), shoes, accent`
   - `acc` (optional): `back`, `body`, `head`, `hand` drawing callbacks (`hand` uses `p.item`: `'rest' | 'use' | 'open'`)
   - `skill.pose(f)` (10 poses) and optional `skill.fx(buf, f)` (aura/effects drawn after the outline)
   - `attackFx(buf, f)` is optional.
   Keep the palette small (a test enforces at most 24 colours) and use hard-edged pixels only.
2. Export it from `roster.js`; it is picked up automatically by `characters.js`.
3. **Generate:** `node tools/gen-sprites.js`. Review the result with a contact sheet (render the PNG strips scaled with `image-rendering: pixelated`).
4. **Game wiring in `index.html`:**
   - add the hero to the `heroes` table (stats are balance decisions, not part of the art),
   - add `id: 'onDeploy'|'onPulse'|'onStack'|'every3'` to `SKILL_MODE` (must equal the config's `skillMode`; a test checks this),
   - add `id: {kind, run}` to `SKILL_FX` using `fxBurst/fxRing/fxBeam/fxSpawn/fxShake` (visual only; use a unique `kind`),
   - if the skill needs a new trigger, call `triggerSkill(u)` where the ability fires.
5. **Run `node --test tests/`.** The sprite tests check sheet sizes, frame counts, hard-edged alpha, ground baseline, distinct silhouettes and skill sheets, and that every hero in the code has a sprite config.

A missing or failed sheet never breaks the game: that hero falls back to the old canvas drawing.

## Visual effects

- Pixel particles are pooled squares (cap `FX_MAX = 300`, oldest recycled).
- `fxLevel` is `full` or `reduced` (the header button toggles it and remembers the choice). Reduced halves particle counts and disables screen shake.
- The universal Faculty Laser is the same gameplay for every faculty (500 damage, 45 s cooldown); only the colour and the particle bitmap differ (`FACULTY_LASER_VFX`).
